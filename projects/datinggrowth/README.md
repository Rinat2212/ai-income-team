# DatingGrowth AI — модуль продвижения Telegram-бота

Модуль для аккуратного продвижения Telegram-бота **@my_daivinchik_2212_bot** через открытые тематические сообщества.

## Принципы MVP
- Каталог сообществ добавляется вручную после проверки публичной ссылки и правил.
- Content Agent формирует три варианта запроса разрешения администратору по краткому описанию проекта (пока шаблонный, без внешней LLM).
- Любой исходящий текст требует ручного одобрения владельца.
- Нет автоматических массовых личных сообщений, обхода ограничений Telegram или публикаций без разрешения администратора.
- SQLite хранит каталог, статусы разрешения, ссылку на правила, контакт, черновики и события переходов.
- DRY_RUN=true включён по умолчанию; MVP не публикует сообщения в группы.

## Запуск
1. Установите Python 3.11+.
2. Создайте Telegram-бота через BotFather и получите токен.
3. Скопируйте projects/datinggrowth/.env.example в projects/datinggrowth/.env, заполните BOT_TOKEN и свой числовой ADMIN_ID.
4. Установите зависимости: pip install -r projects/datinggrowth/requirements.txt.
5. Запустите из корня репозитория: python -m projects.datinggrowth.bot.

## Команды администратора
- /start — проверка доступа и инструкция.
- /addcommunity Название | https://t.me/... | правила/контакт — добавить проверенное открытое сообщество.
- /communities — список каталога.
- /research — очередь сообществ, где разрешение неизвестно или ожидается.
- /permission ID | unknown/requested/allowed/denied | https://t.me/правила или - | контакт/заметка — сохранить результат ручной проверки. Используйте `allowed` только после явного согласия администратора.
- /draft ID сообщества | текст — создать черновик предложения.
- /quality ID черновика — выполнить эвристические проверки текста (не заменяет ручную проверку).
- /queue — показать ожидающие решения черновики.
- /stats — сводка по сообществам, черновикам и отслеженным переходам.

Команда `/research` показывает сообщества, требующие ручной проверки; `/permission` сохраняет статус разрешения и ссылку на правила. Сбор сведений не автоматизирован: никаких сообщений или публикаций без участия владельца.

Команда `/quality ID` проверяет текст на признаки массовой рассылки, действий без разрешения, чрезмерных ссылок и отсутствие явного запроса согласования. Проверка эвристическая: она не гарантирует безопасность и не заменяет чтение правил человеком.\n\nКоманда `/suggest` создаёт три варианта обращения к администратору с запросом разрешения на публикацию. Это шаблонный агент, а не подключённая большая языковая модель. Кнопки «Одобрить» и «Отклонить» меняют статус черновика. Одобрение разрешает использовать текст вручную, но не отправляет его автоматически.

## Аналитика
Бот может считать переходы на deep-link-коды вида https://t.me/<имя_этого_бота>?start=src_<код>. Это измеряет открытие служебного бота, а не запуск целевого @my_daivinchik_2212_bot. Для достоверной атрибуции целевой бот должен сам обрабатывать start payload.
